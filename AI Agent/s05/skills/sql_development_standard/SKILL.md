# BODY: MySQL 规范与慢查询防御准则

## 1. 严苛的 SQL 编写禁令
*   **禁止 `SELECT *`**：必须显式指定目标列名，减少网络 I/O 延迟，并保障数仓底层 Schema 变更时的代码健壮性。
*   **隐式转换禁令**：WHERE 条件中的过滤值类型必须与列定义严格一致。例如字符串类型的 `user_id` 绝不能写成 `WHERE user_id = 12345`，必须写成 `WHERE user_id = '12345'`，防止索引失效导致全表扫描。
*   **模糊查询限制**：禁止使用前置通配符（如 `LIKE '%keyword'`），此类查询无法利用 B+Tree 索引。

## 2. 多表关联与数仓建模规范
*   **驱动表选择**：在进行 `LEFT JOIN` 或 `INNER JOIN` 时，必须确保左表（或过滤后结果集较小的表）为小表，以实现“小表驱动大表”的嵌套循环。
*   **聚合下推优化**：如果需要对大表进行 `JOIN` 后聚合，应优先考虑在子查询中利用索引完成 `GROUP BY` 聚合减量，再与维表进行 `JOIN` 关联。
*   **OR 语句优化**：在同一个索引字段上，尽量使用 `IN (...)` 代替 `OR`，由于 MySQL 优化器对 `IN` 有更佳的基数评估，性能通常优于 `OR`。

## 3. 慢查询预防审查 (防熔断)
*   在大规模更新、删除 (`UPDATE` / `DELETE`) 动作前，必须先将其转化为 `SELECT` 并在命令行执行 `EXPLAIN`，确认 `type` 达到 `range` 或 `ref` 级别，严禁出现 `type = ALL`（全表锁死）的重大事故。
