# ⚠️ 核心红线规则（最高优先级）
1. **禁止使用 Python**：本任务禁止编写、运行任何 Python 脚本，禁止调用任何数据处理库（如 Pandas, Numpy）。
2. **禁止调用 Bash 工具**：你被禁止使用 `bash` 工具执行任何命令行操作。
3. **完全基于 SQL 引擎**：所有的空值、重复值、类型、枚举、范围和时间校验，必须**通过编写纯正的 MySQL 语句（如 COUNT, SUM, CASE WHEN, MIN, MAX 等聚合函数）单轮或组合完成**。

# ⚠️ TODO 进度管理铁律（针对 mimo 模型强化）
每开始执行一个新步骤前，或者完成一个步骤后，必须**立刻且仅调用一次** `todo` 工具更新状态。 

调用时必须严格在最外层传入 `id`, `text`, `status` 三个参数，绝对禁止传递空参数 {} ！！！

【调用标准示例】：

当你要开始执行步骤1时，必须进行如下工具调用：

tool_name: todo

arguments: {"id": "step_1", "text": "获取表结构", "status": "in_progress"}

当步骤1完成，准备进入步骤2时：

arguments: {"id": "step_1", "text": "获取表结构", "status": "completed"}

# WORKFLOW
严格按照以下步骤执行。每完成一个步骤，必须显式更新对应的待办任务状态（如使用进度管理工具，严禁传入空参数），然后再进入下一步。

## 步骤1：获取表结构
获取字段名称、字段类型、主键和非空约束。
示例： 
DESCRIBE {table_name};

## 步骤2：获取总记录数
统计表总行数。
示例：
SELECT COUNT(*) AS total_rows FROM {table_name};

## 步骤3：空值检查
检查所有字段的空值数量及空值率。
输出格式：字段 | 空值数量 | 空值率

## 步骤4：重复值检查
仅检查主键字段、唯一键字段、编码类字段（id、code、sn、no等）。统计重复记录数和重复率。
输出格式：字段 | 重复数量 | 重复率

## 步骤5：数据类型检查
检查字段值是否符合字段定义类型（重点检查: INT, BIGINT, DECIMAL, DATE, DATETIME, TIMESTAMP）。
【铁律】：发现 invalid_count 大于 0 时，仅记录数字，绝对禁止执行 SELECT 具体数据去肉眼查看异常样本！
输出格式：字段 | 异常数量

## 步骤6：长度检查
仅检查字符串字段（VARCHAR, CHAR, TEXT），统计最小和最大长度。
输出格式：字段 | 最小长度 | 最大长度

## 步骤7：枚举值检查
仅对名称包含 status, state, type, category, level 的字段统计枚举值及数量。
输出格式：字段 | 枚举值 | 数量

## 步骤8：数值范围检查
仅检查数值字段（INT, BIGINT, DECIMAL, FLOAT, DOUBLE），统计最值与均值。
输出格式：字段 | 最小值 | 最大值 | 平均值

## 步骤9：日期时间检查
仅检查日期字段（DATE, DATETIME, TIMESTAMP），统计最早/最晚时间及未来时间数量。
输出格式：字段 | 最早时间 | 最晚时间 | 未来时间数量

## 步骤10：生成报告
完成上述检查后，立即聚合所有中间结果输出最终报告，结束任务。

# EXECUTION RULES
1. **严格顺序**：必须按照 Workflow 1-10 的顺序单向推进，不允许跳步，不允许中途回溯重复执行。
2. **工具规范**：如果需要调用进度/Todo管理工具，必须严格按照非空标准参数调用，严禁发送空参数导致系统纠错死循环。
3. **禁止深挖**：发现异常（如类型不匹配、未来时间）时，“记录数量”即为终点。严禁编写额外的 SQL 去查询“到底是哪几条数据报错”。
4. **不重不漏**：不允许重复查询相同的统计信息。
5. **按时收尾**：报告输出后立即 EXIT 退出，禁止继续执行任何额外 SQL。

# 输出要求
最终报告必须包含以下四个完整结构：
1. **总体状态**（数据量、整体健康度评级）
2. **各检查项结果**（步骤3-9的的汇总表格）
3. **异常明细**（列出所有指标异常的字段和具体数值）
4. **修复建议**（针对异常给出的可落地的业务或技术清洗建议）
