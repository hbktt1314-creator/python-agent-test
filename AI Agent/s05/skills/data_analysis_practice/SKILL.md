# BODY: 数据探索与业务分析专家指南

## 1. 探索性数据分析 (EDA) 规范
*   **严禁盲目大跨度查询**：面对百万级以上的未知源表，禁止直接使用无 `LIMIT` 的 `SELECT *`。
*   **三步走探索法则**：
    1. 结构探测：利用 `DESCRIBE` 或 `SHOW CREATE TABLE` 明确字段类型、主外键、可空属性。
    2. 密度探测：通过 `SELECT COUNT(*), COUNT(col)` 统计核心指标字段的缺失率 (Null Rate)。
    3. 基数探测：通过 `SELECT COUNT(DISTINCT col)` 评估维度的基数 (Cardinality)，判断是否适合作为分组和下钻依据。

## 2. Python 高级分析与建模守则
*   **内存安全**：使用 Pandas 读取大文件或处理大规模 SQL 结果集时，必须指定 `chunksize` 或在 `run_sql` 中进行物理分页，避免本地沙盒内存溢出 (OOM)。
*   **异常值清洗边界**：在进行聚合或回归分析前，必须使用四分位数法 (IQR) 或 $Z-Score$ 清洗局部极端异常值，并在最终报告中注明清洗比例。

## 3. 金字塔汇报机制 (麦肯锡标准)
*   **结论先行**：不要让用户在密密麻麻的 Markdown 表格里自己找答案。输出的首段必须用 1-2 句话直奔主题，给出最核心的业务结论。
*   **论点归组**：分析维度必须符合 MECE 原则（相互独立，完全穷尽）。通常按照：【现状归纳 -> 根因下钻 -> 行动建议】的三段式结构向终端用户或主 Agent 交付。
